# Rebuild video-studio around an MCP server

The strategic report's thesis still holds: build a provider-neutral compiler whose durable asset is the `VideoSpec`. Its packaging does not hold. The report treats a `bin/video-studio` CLI on the Bash PATH as the native core of the plugin, and the current Claude Code docs undercut that in two ways. First, **claude.ai and Cowork refuse to install any plugin with a top-level `bin/` directory** ([Components](https://code.claude.com/docs/en/plugins/components)). Second, **`userConfig` secrets and the plugin path variables never reach commands Claude runs through the Bash tool**. Sensitive keys can only be delivered to MCP server configs and hook processes ([Manifest reference](https://code.claude.com/docs/en/plugins/manifest-reference)). A BYOK plugin that holds Runway, Kling, HeyGen and ElevenLabs keys should therefore ship its engine as a **bundled stdio MCP server**. The CLI stays under `scripts/` for development and CI. Four more verified facts change the build. `ffmpeg-static` ships **GPL-3.0-or-later** binaries ([npm](https://registry.npmjs.org/ffmpeg-static)). **HeyGen v1/v2 retire on October 31, 2026**, five weeks from this snapshot ([HeyGen](https://developers.heygen.com/endpoint-version-comparison.md)). HyperFrames is pre-1.0 and shipped **10 releases in about 30 hours** ([GitHub releases](https://api.github.com/repos/heygen-com/hyperframes/releases)). Provider output URLs expire, **within 24–48 h on Runway** ([Runway](https://docs.dev.runwayml.com/assets/outputs/)). The OpenAI Sora shutdown is confirmed as the report stated.

## The plugin format rewards MCP and punishes `bin/`

The manifest lives at `.claude-plugin/plugin.json`, and **`name` (kebab-case) is its only required field**. Every other component goes at the plugin root: `skills/<name>/SKILL.md`, `agents/*.md`, `hooks/hooks.json`, `.mcp.json`, `bin/`, `output-styles/`, `workflows/` and `settings.json`. Every path in the manifest must start with `./` and stay inside the plugin root. Manifest keys interact with the default directories in three ways. Setting `commands` or `agents` *replaces* the default directory scan, `skills` *adds* to it, and `hooks`/`mcpServers` *merge* with the default files. The easiest safe choice is to leave the component keys out. Unknown top-level keys are stripped with a warning. Unknown keys inside `userConfig` options are hard errors, and the plugin will not load. A root `CLAUDE.md` is **not** loaded as context ([Manifest reference](https://code.claude.com/docs/en/plugins/manifest-reference)).

The execution surface is where the report goes wrong. Files in `bin/` are appended to the Bash PATH *after* the user's own entries, so a plugin cannot shadow system commands. But "claude.ai and Cowork don't install a plugin that has a top-level `bin/` directory". The docs advise moving executables to `scripts/` and calling them as `${CLAUDE_PLUGIN_ROOT}/scripts/<name>` ([Components](https://code.claude.com/docs/en/plugins/components); [Host a marketplace](https://code.claude.com/docs/en/plugins/host-marketplace)). The environment table settles the secrets question. **Hooks** receive `CLAUDE_PLUGIN_ROOT`, `CLAUDE_PLUGIN_DATA`, `CLAUDE_PROJECT_DIR` and `CLAUDE_PLUGIN_OPTION_<KEY>`. **MCP stdio servers** receive `CLAUDE_PLUGIN_ROOT` and `CLAUDE_PLUGIN_DATA`, and `${user_config.KEY}` is substituted into their `command`, `args` and `env`. Skill and agent Markdown gets inline substitution only, and **sensitive values become a placeholder** there. The docs say it directly: "The variables aren't present in the environment of commands Claude runs through the Bash tool" ([Manifest reference](https://code.claude.com/docs/en/plugins/manifest-reference)).

`userConfig` options are strict objects with `type` (`string|number|boolean|directory|file`), `title` and `description`, plus optional `required`, `default`, `sensitive`, `multiple` and `options`. The `options` picker needs v2.1.271+, and older clients cannot load a plugin that uses it. Sensitive values go to the OS credential store, and the rest go to `pluginConfigs` in `settings.json`. The configuration prompt appears only in the interactive `/plugin` UI. **`claude plugin install` from a shell never prompts**, so CI and scripted installs must pass `--config KEY=VALUE` ([Components](https://code.claude.com/docs/en/plugins/components)). Plugin MCP tools are named `mcp__plugin_<plugin>_<server>__<tool>`. `mcpServers` can point at an inline map, a JSON file, or a `.mcpb`/`.dxt` bundle ([Manifest reference](https://code.claude.com/docs/en/plugins/manifest-reference)). The engine's data directory is `${CLAUDE_PLUGIN_DATA}`, which resolves to `~/.claude/plugins/data/<id>/`. It survives updates and is **deleted on uninstall unless `--keep-data` is passed**. `${CLAUDE_PLUGIN_ROOT}` changes on every update, so the engine must never write state there.

Skills follow the six-field rule. Claude Code accepts many fields in skill frontmatter, including `argument-hint`, `disable-model-invocation`, `context: fork`, `paths` and `hooks`. But **claude.ai uploads and the Skills API hard-reject anything beyond `name`, `description`, `license`, `compatibility`, `metadata` and `allowed-tools`** ([Skills](https://code.claude.com/docs/en/skills)). The open spec limits `name` to 64 characters, lowercase, matching its directory, and `description` to 1,024 characters ([Agent Skills spec](https://agentskills.io/specification)). The listing truncates `description` plus `when_to_use` at 1,536 characters. Keep each SKILL.md under 500 lines. A skill invocation's `allowed-tools` grant clears at the next user message. Plugin skills are invoked as `/video-studio:<skill>`, and `commands/` is legacy.

Agents (`agents/*.md`) require `name` and `description` and are namespaced `video-studio:<name>`. Plugin agents **ignore `permissionMode`, `hooks`, `mcpServers` and `initialPrompt`**, so MCP servers and hooks must be declared at plugin level ([Components](https://code.claude.com/docs/en/plugins/components)).

Hooks go in `hooks/hooks.json` under a top-level `"hooks"` key. They fire whether or not the plugin's skills are ever used, and they also run in subagents. Use **exec form** (`command` plus `args`) whenever a path placeholder is involved, because `${user_config.*}` is not substituted in shell form since v2.1.207. The command-hook timeout defaults to 600 s ([Hooks](https://code.claude.com/docs/en/hooks)). Enterprise `allowManagedHooksOnly` silently disables plugin hooks, so no correctness-critical logic should live only in a hook.

For distribution, one repo can hold `plugin.json` plus a `.claude-plugin/marketplace.json` with `{"name":"…","owner":{"name":"…"},"plugins":[{"name":"video-studio","source":"./"}]}`. Users then run `/plugin marketplace add owner/repo` and `/plugin install video-studio@<marketplace>` ([Publish](https://code.claude.com/docs/en/plugins/publish)). Names such as `claude-plugins-official`, `claude-community`, `npm` and `claudeai-*` are reserved ([Marketplace reference](https://code.claude.com/docs/en/plugins/marketplace-reference)). `claude plugin validate --strict --json <path>` exits 0 on pass, 1 on failure (or on warnings under `--strict`) and 2 on a validator error. Run from a marketplace root, it does **not** check skill, agent or hook files, so validate the plugin directory separately. `claude --plugin-dir ./video-studio` loads the plugin locally as `@inline` ([CLI reference](https://code.claude.com/docs/en/plugins/cli-reference)). If `version` is set and not bumped, users stay on the old copy. Public listing goes through the **community marketplace** form. The docs say the official marketplace "doesn't take submissions through these forms" ([Publish](https://code.claude.com/docs/en/plugins/publish)), which contradicts the older [claude-plugins-official README](https://github.com/anthropics/claude-plugins-official).

## HyperFrames is the default renderer, pinned exactly, with FFmpeg supplied by the user's system

HyperFrames is **Apache-2.0, v0.8.74, about 52.9k stars**, and the repo was created only on 2026-03-10 ([GitHub API](https://api.github.com/repos/heygen-com/hyperframes)). Compositions are plain HTML. Each clip carries `data-start`, `data-duration` and `data-track-index`, and animation timelines are created `paused` and registered on `window.__timelines`. Rendering seeks frames by integer math and captures each one with Chrome's `HeadlessExperimental.beginFrame`. The docs forbid `Date.now()`, timers, unseeded randomness and mid-render fetches ([Determinism](https://github.com/heygen-com/hyperframes/blob/main/docs/concepts/determinism.mdx)). The one-call Node API is `createRenderJob({inputPath, outputPath, width, height, fps})` plus `executeRenderJob(job, onProgress)` from `@hyperframes/producer`. It mixes `<audio>`/`<video>` elements and outputs MP4 (H.264/AAC), WebM with alpha, ProRes 4444, PNG sequences or HLS ([producer README](https://github.com/heygen-com/hyperframes/blob/main/packages/producer/README.md)).

Four constraints matter. HyperFrames needs **Node ≥ 22 and a separately installed FFmpeg**, and the producer has no bundled FFmpeg dependency. **macOS and Windows fall back to slower screenshot capture**, because BeginFrame is the default only on Linux headless-shell. Rendering is bit-exact across machines only with `render --docker`, which pins Chromium, fonts and encoder. And a pre-1.0 package with several releases a day demands an **exact version pin behind an adapter interface**. HyperFrames also publishes 21 agent skills, including caption components such as `caption-pill-karaoke`, which can be adapted rather than rewritten ([README](https://github.com/heygen-com/hyperframes)).

Remotion's licensing concern is confirmed. The free license covers individuals, for-profit organizations with **up to 3 employees**, non-profits and evaluation. Anyone else needs a Company License ([LICENSE.md](https://github.com/remotion-dev/remotion/blob/main/LICENSE.md)), priced at $0.01/render with a $100/month minimum for "Automators", $25/seat/month for "Creators", or from $500/month for Enterprise ([remotion.pro](https://www.remotion.pro/license)). An open Remotion 5.0 PR would make **contractors count toward team size** ([PR #3750](https://github.com/remotion-dev/remotion/pull/3750)). Remotion remains more mature, and HyperFrames' own maintainers concede that point for Lambda ([comparison](https://github.com/heygen-com/hyperframes/blob/main/docs/guides/hyperframes-vs-remotion.mdx)). The alternatives are weaker. Revideo is MIT but uses TypeScript generator scenes. Motion Canvas's last npm release was December 2024, and editly's was December 2022 ([npm](https://registry.npmjs.org/editly)).

FFmpeg is the licensing trap the report underplayed. `ffmpeg-static` 5.3.0 is **GPL-3.0-or-later** and ships FFmpeg 6.1.1 built by johnvansickle, evermeet, osxexperts and gyan.dev ([README](https://github.com/eugeneware/ffmpeg-static)). `@ffmpeg-installer/ffmpeg` is labelled LGPL but has not been published since 2021. `ffprobe-static`'s "MIT" label covers only the wrapper. LGPL compliance requires building without `--enable-gpl` and with dynamic linking ([ffmpeg.org/legal](https://ffmpeg.org/legal.html)). That excludes libx264, which most pipelines expect. The workable policy is to **resolve system `ffmpeg`/`ffprobe` first (or a `FFMPEG_PATH` override), treat `ffmpeg-static` as an opt-in fallback with a GPL notice, and preflight `-buildconf` for `--enable-libass` and `--enable-libx264`**. The QA stage can rely on documented filters: two-pass `loudnorm`, `blackdetect`, `freezedetect` and `silencedetect`. Captions are burned in through `subtitles`/`ass` with ASS `\k`/`\kf` karaoke tags timed in centiseconds ([ffmpeg-filters](https://ffmpeg.org/ffmpeg-filters.html); [Aegisub](https://aegisub.org/docs/latest/ass_tags/)).

**Runway is the widest single adapter.** Its API now hosts Veo 3.1, Seedance 2/2.5, Hailuo 3, Wan 3 and Grok Imagine alongside `gen4.5`, `gen4_turbo` and `aleph2` ([Models](https://docs.dev.runwayml.com/guides/models/)). Credits cost **$0.01 each**. Per second of output, gen4.5 is 12 credits, gen4_turbo 5, veo3.1 20 without audio or 40 with it, and aleph2 28 with a 56-credit minimum ([Pricing](https://docs.dev.runwayml.com/guides/pricing/)). The Model Router is real. You call `POST /v1/generate/video|image|audio` with `{configId, input}` and no model. Configs set a cost, latency or quality preference, per-modality hard credit caps, and allow or deny lists (an allow list never picks up new models automatically). `dryRun: true` returns the chosen model and an estimated cost without spending ([Generating via router](https://docs.dev.runwayml.com/model-routers/generating); [Configuration](https://docs.dev.runwayml.com/model-routers/configuration/)). The exact field names for the cost values were not captured. The gen4.5 image-to-video limits (2–10 s, ratios such as `1280:720`/`720:1280`) come from third-party mirrors ([Runware](https://runware.ai/docs/models/runway-gen-4-5/guides/directing-motion)).

**Kling is the least verified adapter.** Models run up to `kling-v3.0` for T2V, I2V and motion control. Documented parameters include `mode` std/pro, a duration of "3–15s typical", `sound` (v2.6+ pro only), `negative_prompt` of up to 2,500 characters, `cfg_scale` from 0 to 1, `multi_shot` and `callback_url` ([AI SDK](https://ai-sdk.dev/providers/ai-sdk-providers/klingai)). Billing is by prepaid resource packs, separate from web plans. Per-second prices of about $0.08–$0.42 are third-party and unverified ([costbench](https://costbench.com/software/ai-media-apis/kling-api/)). fal.ai is a reasonable fallback transport for Kling, Veo and Hailuo ([fal Veo 3.1 Fast](https://fal.ai/models/fal-ai/veo3.1/fast)).

**HeyGen must be built on v3 only.** v1/v2 are "supported until October 31, 2026". Legacy responses carry a `warning` object that names the v3 replacement, for example `POST /v2/video/generate` → `POST /v3/videos` ([Version comparison](https://developers.heygen.com/endpoint-version-comparison.md)). `POST /v3/videos` is a discriminated union, `type: avatar | image | cinematic_avatar | studio`. Its speech input is exactly one of `script`+`voice_id`, `audio_url` or `audio_asset_id`. For an ElevenLabs-first pipeline, pass audio (≤10 min, ≤50 MB) so the voice and its timings stay canonical. Webhooks use an HMAC-SHA256 `signature` over the raw body, retry for 24 h, and require a 2xx response within 10 s. Deduplicate on `video_id` plus `event_type` ([Webhooks](https://developers.heygen.com/docs/webhooks.md)). Pay-as-you-go allows **10 concurrent workflows**, and scripts are capped at 5,000 characters ([Usage limits](https://developers.heygen.com/docs/usage-limits.md)). Digital-twin consent (`consent_status` `pending` → `approved`) applies only to twins; photo avatars return `null` ([Consent](https://developers.heygen.com/docs/avatar-consent.md)). Official API pricing pages returned 404. The only per-second figures, $0.05/s for photo avatars and $0.0667/s for digital twins at 1080p, come from a June 2026 third-party blog ([realtimeavatar.ai](https://realtimeavatar.ai/blog/heygen-api-pricing-explained)).

**Sora is gone.** OpenAI removed the Videos API and every `sora-2*` model on **September 24, 2026**, after notice on March 24, and named no replacement ([OpenAI deprecations](https://developers.openai.com/api/docs/deprecations)). Do not build even a "compatibility" adapter, because there is nothing left to call.

## Word timings come from TTS alignment first, local ASR second

`POST /v1/text-to-speech/{voice_id}/with-timestamps` returns `audio_base64` plus **character-level** `alignment` and `normalized_alignment` arrays. The adapter must group characters into words and, for chunked scripts, offset each chunk by the cumulative audio duration. It can pass `previous_request_ids` to keep prosody continuous across chunks and a `seed` for reproducibility ([API ref](https://elevenlabs.io/docs/api-reference/text-to-speech/convert-with-timestamps)). The models in play are `eleven_v3` (5k characters), `eleven_multilingual_v2` (10k, the default) and `eleven_flash_v2_5` (40k, half price). **`eleven_turbo_*` is deprecated** ([Models](https://elevenlabs.io/docs/models)). TTS costs **$0.10 per 1K characters** on standard models and $0.05 on Flash, and Scribe v2 STT costs $0.22/hour ([Pricing](https://elevenlabs.io/pricing/api)). Both zero-retention mode (`enable_logging=false`) and the EU, India and Singapore residency hosts are **Enterprise-only** ([Data residency](https://elevenlabs.io/docs/overview/administration/data-residency)). The policy engine must treat them as entitlements, not defaults. When the audio came from somewhere else, `POST /v1/forced-alignment` with the known script returns word `{text,start,end,loss}` ([Forced alignment](https://elevenlabs.io/docs/api-reference/forced-alignment/create)). OpenAI `gpt-4o-mini-tts` returns no timestamps and requires an AI-voice disclosure to listeners ([OpenAI TTS](https://developers.openai.com/api/docs/guides/text-to-speech)). Kokoro-82M (Apache-2.0, `kokoro-js`) is the offline fallback. Piper is now **GPL-3.0** under OHF-Voice ([piper1-gpl](https://github.com/OHF-Voice/piper1-gpl)).

For recorded voiceovers, **whisper.cpp** (MIT, v1.9.4, with Metal and Core ML on Apple Silicon) is the Node-friendly local engine ([whisper.cpp](https://github.com/ggml-org/whisper.cpp)). `@remotion/install-whisper-cpp` wraps it neatly: `transcribe()` takes 16 kHz WAV input and `t_dtw` token timestamps are recommended ([docs](https://www.remotion.dev/docs/install-whisper-cpp/transcribe)). But its npm license field is "SEE LICENSE IN LICENSE.md", the Remotion license, which conflicts with the "MIT" label in its docs ([npm](https://registry.npmjs.org/@remotion%2Finstall-whisper-cpp)). Shelling out to a user-installed whisper.cpp binary avoids the question. faster-whisper's last release was v1.2.1 in October 2025, and it documents CUDA but not Metal ([faster-whisper](https://github.com/SYSTRAN/faster-whisper)). That makes it a poor default for a Node plugin on Macs. WhisperX gives tighter wav2vec2-aligned boundaries but needs PyTorch, so it fits as an optional `uvx whisperx` precise mode ([WhisperX](https://github.com/m-bain/whisperX)). Whichever source produces them, a single canonical `{word, startMs, endMs}` JSON should drive the HTML captions, the ASS karaoke track and the SRT/VTT sidecars.

## The Node core can be dependency-light and fully bundleable

The engine should require **Node ≥ 22.13**. HyperFrames, unpdf and secretlint all need Node 22+. `node:sqlite` has been unflagged since 22.13 and became a Stability 1.2 release candidate in 24.15+ ([Node docs](https://nodejs.org/docs/latest-v24.x/api/sqlite.html)). Built-in `node:sqlite` removes the native-ABI risk that better-sqlite3 prebuilds carry ([better-sqlite3](https://github.com/WiseLibs/better-sqlite3)). That keeps the engine bundleable into one file, which matters because the plugin runs on whatever Node the user has. Whether Node 22.x prints an ExperimentalWarning is untested.

|---|---|---|---|
| URL → markdown | defuddle (`markdown:true`, linkedom), Readability fallback, Playwright only on thin pages | MIT | [defuddle](https://github.com/kepano/defuddle) |
| PDF | unpdf (PDF.js v5 serverless) | MIT | [unpdf](https://github.com/unjs/unpdf) |
| DOCX | mammoth → HTML → turndown; **no sanitization of untrusted input** | BSD-2 | [mammoth](https://github.com/mwilliamson/mammoth.js) |
| PPTX/office | officeparser v7 | MIT | [officeParser](https://github.com/harshankur/officeParser) |
| Repo | repomix library (.gitignore, secretlint, tree-sitter compress) + secretlint gate; gitleaks optional | MIT | [repomix](https://github.com/yamadashy/repomix); [secretlint](https://github.com/secretlint/secretlint) |
| Schemas | zod v4 → `z.toJSONSchema()` (Draft 2020-12, `.meta()` ids, registries) | MIT | [zod](https://zod.dev/json-schema) |
| Queue | p-queue (in-memory, ESM-only) + SQLite jobs table for durability | MIT | [p-queue](https://github.com/sindresorhus/p-queue) |
| Bundler | tsdown or esbuild; **tsup is unmaintained** | MIT | [tsup](https://github.com/egoist/tsup) |
| Screenshots | `playwright-core` + `channel:'chrome'`; full Chromium is ~281 MB | Apache-2.0 | [Playwright](https://playwright.dev/docs/browsers) |

The IR schemas should avoid constructs zod cannot represent in JSON Schema. Use ISO-string dates, not `z.date()`, and no transforms. CI should regenerate the committed `.schema.json` files and diff them. Content-addressed cache keys should hash canonical JSON of `{kind, inputDigest, extractor version, options, irSchemaVersion}` with sha256, and writes should be atomic (write to a temp file, then rename).

## Decisions this implies

| # | Decision | Driven by |
|---|---|---|
| 1 | **Ship the engine as a plugin stdio MCP server** (`node ${CLAUDE_PLUGIN_ROOT}/dist/mcp.mjs`). Provider keys enter through `env: {"RUNWAYML_API_SECRET": "${user_config.runway_key}", …}` with `sensitive: true`. Skills call MCP tools, not Bash. | Secrets don't reach Bash; MCP `env` receives `${user_config.*}` |
| 2 | **No top-level `bin/`.** Put the dev/CI CLI in `scripts/` or a separate npm package, reading standard env vars (`RUNWAYML_API_SECRET`, `ELEVENLABS_API_KEY`, `KLINGAI_API_KEY`, `HEYGEN_API_KEY`). | claude.ai/Cowork reject `bin/` |
| 3 | Expose long operations as **job tools** (`render_submit`, `job_status`, `job_resume`), not one blocking call. The MCP process owns polling and **downloads outputs the moment a task succeeds**, recording hashes in the SQLite ledger under `${CLAUDE_PLUGIN_DATA}`. Project artifacts go in the user's project folder, because the data dir is deleted on uninstall. | Runway 24–48 h URLs, HeyGen presigned URLs, unknown Kling retention |
| 4 | **Bundle to a single ESM file** with `node:sqlite`, `engines: {"node": ">=22.13"}`, and heavy optional dependencies (Playwright, HyperFrames/Chrome) loaded lazily. Where a dependency cannot be bundled, a `SessionStart` exec-form hook installs it into `${CLAUDE_PLUGIN_DATA}`. | Native-ABI risk; the documented dependency pattern |
| 5 | Use HyperFrames as the default renderer, **pinned to an exact version behind a `Renderer` interface**, with golden-render tests on each bump. Remotion is an opt-in adapter that warns about the license. | Pre-1.0 release velocity; Remotion's 3-employee limit |
| 6 | **System FFmpeg first**, `ffmpeg-static` only as an opt-in fallback with a GPL-3.0 notice, and a `doctor` preflight for libass and libx264. | ffmpeg-static is GPL-3.0; HyperFrames needs system FFmpeg |
| 7 | **Build HeyGen against v3 from day one**, send an `Idempotency-Key` derived from a hash of the scene, gate twins on `consent_status === "approved"`, and pass ElevenLabs audio rather than script. | v1/v2 retire 2026-10-31 |
| 8 | Use the Runway router's `dryRun` for estimates where available, and local `credits/s × duration × $0.01` otherwise. Never add Sora. | Router verified; Sora removed |
| 9 | Keep portable skills to the six spec fields and put plugin-only fields in plugin-only skills. Set `disable-model-invocation: true` on spend-incurring skills. | claude.ai rejects extra frontmatter |
| 10 | Put `claude plugin validate --strict` on both the marketplace root **and** the plugin directory in CI. Bump `version` on every release, or omit it. Self-host the marketplace and submit to the community marketplace. | Validator scope; submission policy |

Decision 1 is an inference from the documented variable-resolution table, not an explicitly documented pattern for this use case. The docs describe no mechanism that exposes userConfig to Bash. The alternative workaround, a hook writing keys to a 0600 file, puts secrets on disk and should be rejected.

## Conclusion

The research moves the architectural center of gravity. The strategic report placed the "compiler" in a CLI that Claude shells out to. The platform's security model instead places anything that holds credentials and runs long provider jobs in an **MCP server that Claude Code launches with secrets injected**. That is also the only shape that installs on claude.ai and Cowork. The change is cheap now and expensive later: the adapter interface, job ledger and `VideoSpec` survive intact, and only the invocation layer moves. The design fits the fact that provider URLs expire, since a resident process that polls and downloads is safer than a Bash call that can be interrupted.

The remaining risk sits in the least-documented dependencies, not the most-hyped ones. Kling's endpoints, status names, retention and pricing all need a logged-in verification pass before its adapter is written. HeyGen's official prices and URL TTLs are undocumented. HyperFrames changes faster than any sane test suite can track. Build conformance tests and golden renders first, treat every unverified field as a feature flag, and ship the HeyGen v3 path before October 31.
